# Changelog — Ascendant Attributes


## [1.0.1] - 2026-08-12

### Change

- **Nombre de JAR con versión del cargador**: el artefacto ahora se compila como `ascendant_attributes-26.2-neoforge-26.2.0.37-beta-1.0.1.jar` (se añade la versión de cargador/NeoForge al nombre del archivo). Empaquetado y documentación; sin cambios de funcionalidad.

## [1.0.0] - 2026-08-10

### Release

- **Primera versión estable.** Con el fix de traducciones al español (`0.0.0-beta.5`) y todo el roadmap de port completado en fases anteriores (Fases 0-13, ver entradas de `0.0.0-beta.1`/`.2`/`.4` más abajo), el mod pasa de línea beta a **release** `1.0.0` (SemVer): 20 atributos personalizados, 7 efectos de estado, GUI de inspección de atributos, fórmulas de combate configurables (EvalEx), 7 mixins verificados en runtime, compat opcional con Curios, arte propio completo y localización en-US/es-ES.
- `README.md` y `docs/curseforge/project_description.md` actualizados — ambos seguían describiendo el scaffold inicial (`0.0.0-beta.1`, "sin funcionalidades implementadas") pese a que el port llevaba completado desde hace varias betas.
- Sin cambios de código respecto a `0.0.0-beta.5` — este release marca la estabilidad del port, no introduce funcionalidad nueva.

## [0.0.0-beta.5] - 2026-08-10

### Fix

- **Traducciones al español faltantes**: no existía `assets/ascendant_attributes/lang/es_es.json` — el mod solo tenía `en_us.json`. En cliente con idioma español, los nombres base de atributos vanilla se veían en español (los provee Minecraft), pero todo lo propio del mod (descripciones de atributos, GUI, efectos de estado, mensajes de muerte, nombres de pociones custom) caía al fallback en inglés.
- Añadido `lang/es_es.json` con las 130 claves traducidas (mismos placeholders `%s`/`%1$s` que el original).

## [0.0.0-beta.4] - 2026-08-07

### Change

- **Code quality improvements**: Removed unnecessary type casts in the main class (`AscendantAttributes.java`):
  - Removed cast to `MobEffect` when adding attribute modifiers (NeoForge 26.2 returns effect directly from `.value()`)
  - Removed cast to `Attribute` when calling `setSyncable()` (NeoForge 26.2 returns attribute directly from holders)
- Improves code clarity without changing functionality
- Build verified green, all mixins and registrations confirmed working

## 0.0.0-beta.2

- **Primera subida real a CurseForge con contenido funcional.** Todo el trabajo listado bajo `0.0.0-beta.1` más abajo (Fases 1-13 del roadmap) se hizo sin subir el `mod_version` correspondiente — el único archivo publicado hasta ahora seguía siendo el scaffold vacío original (file ID `8572977`, verificado vía API de CurseForge). Este bump corrige eso: empaqueta el port completo (atributos, efectos, GUI, mixins, compat Curios, arte propio) como la versión que realmente se sube.
- Ver `docs/curseforge/versions/0.0.0-beta.2.md` para las release notes de esta versión.
- Subido a CurseForge vía `curseforge-upload.ps1` (file ID `8575449`, 292 KB — verificado vía API, frente a los 21 KB del scaffold original).

Ver `docs/ASCENDANT_ATTRIBUTES_RENAME_MAP.md` y `docs/ROADMAP_ASCENDANT_ATTRIBUTES.md`.
- Fix: `generateModMetadata` (heredado de `codex-docs/mod_template`) buscaba la plantilla en `src/main/templates/` pero el archivo vivía en `src/main/resources/templates/...`, así que `META-INF/neoforge.mods.toml` nunca se expandía ni llegaba al JAR final (el mod no habría cargado en el juego). Movido a `src/main/templates/META-INF/neoforge.mods.toml`. Mismo bug detectado en el JAR ya construido de `ascendant_equipment` — pendiente de corregir allí también.
- Icono propio integrado (`assets/ascendant_attributes/icon.png`, `logoFile` activo en `neoforge.mods.toml`).
- Proyecto CurseForge creado: ID `1638518`.
- JAR: `ascendant_attributes-26.2-neoforge-0.0.0-beta.1.jar` (naming alineado con el resto de mods del workspace, `archivesName` incluye versión de Minecraft y framework).
- Subido a CurseForge vía `curseforge-upload.ps1` (file ID `8572977`). `relations` (Common Toolkit required, Curios API Updated optional) no se pudieron declarar en esta subida — CurseForge rechazó los slugs (`errorCode 1018`), probablemente por proyectos aún no públicos. Pendiente añadirlas manualmente o reintentar por API — ver `docs/curseforge/project_vars.md`.
- Fases 1-4 del roadmap implementadas (delegado a OpenCode, `opencode-go/deepseek-v4-flash`, verificado el diff y el build de forma independiente): clase principal `AscendantAttributes` (reemplaza el stub del scaffold), `AttributesConfig` (fórmulas de combate configurables vía EvalEx real, `com.udojava:EvalEx:2.7` bundleada con `jarJar`), `AscendantAttributesObjects` (registro completo: 20 attributes, 7 mob effects, attachments, sonidos, damage types, potions, tags, equipment slots), `CombatRules`, `AttributeHelper`, `CooldownTracker`, `AbilityCooldowns`, los 7 mob effects propios (Bleeding, Detonation, Flying, Grievous, Knowledge, Sundering, Vitality) y los 7 modifiers de stack/equipo. Access transformer añadido para `LivingEntity.lastHurt` (necesario para `AuxDmgTracker`). Eliminado el `Config.java` demo del scaffold (ModConfigSpec) y las llaves de idioma de ejemplo, sin relación con el mod real. Llamadas a subsistemas de fases posteriores (cliente, red, comandos, datagen, compat Curios) quedan marcadas con `// TODO(Phase N)` explícitos. Build verde (`ascendant_attributes-26.2-neoforge-0.0.0-beta.1.jar`), sin residuos del mod original salvo la atribución obligatoria en `credits`.
- Fases 5-6 del roadmap implementadas (delegado a OpenCode, mismo modelo, verificado el diff y el build de forma independiente): `impl.AttributeEvents` (~430 líneas, ~20 handlers de eventos NeoForge — draw speed, life steal/overheal, daño auxiliar fuego/frío, golpes críticos, esquiva, XP de bloques/mobs, curación, daño de flechas/proyectiles, modifiers de stack/equipo, recarga de config, sincronización de datapacks, tick de `AuxDmgTracker`), `event.AttributesCommandEvent` (renombrado de `ApotheosisCommandEvent`, residuo de marca sin relación funcional), `payload.ConfigPayload` y `payload.CritParticlePayload` (sincronización cliente/servidor). Wireado en `AscendantAttributes`: `AttributeEvents` registrado en el bus, ambos payloads registrados vía `PayloadHelper` de Common Toolkit. Access transformer ampliado con `AbstractArrow.baseDamage`/`piercingIgnoreEntityIds` (privados en MC 26.2, igual que en el original). Los dos métodos `cmds(...)` (registro del comando de admin) quedan con `TODO(Phase 7)` a la espera de `BonusModifierCommand`; `CritParticlePayload.handleClient` queda con `TODO(Phase 9)` a la espera del cliente. Build verde, sin residuos del original salvo la atribución en `credits`.
- Fase 7 del roadmap implementada (delegado a OpenCode, mismo modelo, verificado el diff y el build de forma independiente): `commands.BonusModifierCommand` (comando de administración que añade un modifier de atributo temporal al ítem en mano), wireado en los dos `cmds(...)` de `AttributeEvents`. El comando original era literalmente `/apoth add_bonus_modifier` — residuo de marca visible al jugador, no solo interno — renombrado a **`/ascattr add_bonus_modifier`**. Build verde, sin residuos del original.
- Fase 8 del roadmap implementada (delegado a OpenCode, mismo modelo, verificado el diff, el build y el datagen de forma independiente): `data.MixProvider` (generador de brewing mixes vía `com.skd.commontoolkit.util.data.DynamicRegistryProvider`/`MixRegistry`, wireado en `AscendantAttributes.data()`), 5 damage types + 2 tags de damage type portados como JSON de mano (namespace y `message_id` renombrados). Ejecutado `./gradlew.bat runData`: genera 37 brewing mixes en `src/generated/resources/data/ascendant_attributes/common_toolkit/brewing_mixes/` (el segmento `common_toolkit/` viene del registry id de `MixRegistry`, análogo al `placebo/` del original), commiteados junto al resto (convención estándar de datagen en NeoForge).
- Fix: `neoforge.mods.toml` declaraba `versionRange="[0.0.0,)"` para Common Toolkit y `"[15.0.0,)"` para Curios API Updated — rangos que **excluyen** las versiones beta reales de esos jars (`0.0.0-beta.1`, `15.0.0-beta.2+26.2`, que en SemVer ordenan por debajo de `0.0.0`/`15.0.0` al llevar sufijo de pre-release). El bug no se detectaba en `build` (no arranca FML), solo lo reveló `runData` al intentar cargar el juego. Corregido a `[0.0.0-beta.1,)`/`[15.0.0-beta.2,)`.
- Fase 9 del roadmap implementada (delegado a OpenCode, mismo modelo, verificado el diff y el build de forma independiente): overlay de atributos en el inventario (`client.AttributesGui`, 549 líneas), tooltips de efectos/pociones, posicionamiento del botón HUD, y el manejador de eventos de cliente `AttributesLibClient` → renombrado a **`AscendantAttributesClientHandler`** (colisión de nombre evitada con el stub `AscendantAttributesClient` ya existente del scaffold). Wireado en `AscendantAttributes` (registro en bus de eventos + `ModBusSub`) y en `CritParticlePayload` (`spawnCritParticle`, renombrado de `apothCrit`). Requirió varias iteraciones por cambios reales de API entre la versión original (26.1.2) y esta (26.2): `I18n.exists` → `Language.getInstance().has`, `Gui.getMobEffectSprite` → `Hud.getMobEffectSprite`, `ChatFormatting.getColor()`/`getChar()` eliminados → `TextColor.fromLegacyFormat(...).getValue()` / `toString()`. Comando de debug del cliente renombrado de `apothic_attributes_client` a `ascendant_attributes_client`; reload listener `al_config` → `attributes_config`. AT ampliado con los mismos campos privados que el original necesitaba en `AbstractContainerScreen`/`AbstractRecipeBookScreen`/`MobEffect`/`AttributeInstance`. Build verde, sin residuos del original.
- Fase 10 del roadmap implementada (delegado a OpenCode, mismo modelo, verificado el diff, el build y la carga real de los mixins en runtime — `runServer` arrancó completo con los 6 mixins de servidor aplicados sin errores, sin fallback a asumir que compilar basta): los 7 mixins (`CombatRulesMixin`, `EntityMixin`, `LivingEntityMixin`, `NearestAttackableTargetGoalMixin`, `PlayerMixin`, `ThrownTridentMixin`, `client.AbstractContainerScreenMixin`) — caída con gravedad del atributo GRAVITY, seguimiento de muertes por daño auxiliar, marcaje de sweep attacks, no caerse de bordes, escalado de daño de tridente, rango de detección de mobs, fix de arrastre de ratón en pantallas de inventario. Creado `ascendant_attributes.mixins.json` (no existía infraestructura de mixins en el proyecto) y descomentado el bloque `[[mixins]]` en `neoforge.mods.toml`. Resuelta la colisión de nombre entre el `net.minecraft.world.damagesource.CombatRules` vanilla (objetivo del mixin) y nuestro propio `api.CombatRules` (ya portado en Fases 1-4) cualificando el vanilla directamente en `@Mixin(value = ...)` sin importarlo. La clave NBT `ascendant_attributes.killed_by_aux_dmg` de `PlayerMixin` coincide exactamente con la ya usada en `AttributeEvents` (Fase 5-6). Verificado sin solapamiento real con el mixin homónimo de Common Toolkit sobre `AbstractContainerScreen` (ese solo implementa una interfaz marcador, sin inyecciones). MixinExtras confirmado disponible transitivamente vía el plugin de NeoForge, sin dependencia extra en `build.gradle`. Build verde, sin residuos del original.
- Fase 11 del roadmap implementada (delegado a OpenCode, mismo modelo, verificado el diff y el build de forma independiente; comprobado además que el mod arranca sin problemas tanto con Curios cargado como sin él): `compat.CurioEquipmentSlot` (equipment slot respaldado por un tipo de slot de Curios) y `compat.CuriosCompat` (integra los modifiers de atributo de objetos en slots de Curios con el sistema propio de `StackAttributeModifiers`, y expone los curios equipados como fuente de modifiers en la GUI de atributos). Wireado en `AscendantAttributes.setup()` tras el `ModList.get().isLoaded("curios")` ya existente. Es la última fase de código de esta ronda — quedan Fase 12 (arte propio) y Fase 13 (QA de paridad), de naturaleza distinta al resto. Build verde, sin residuos del original.
- Fase 12 (arte propio) — assets de textura y sonido generados por el usuario (arte propio, no copiado del original ARR), integrados: 7 iconos de mob effect (`textures/gui/sprites/mob_effect/`, nombres sin prefijo — Minecraft deriva la ruta automáticamente del ID del efecto vía `Hud.getMobEffectSprite`, no se puede renombrar sin romper el render), panel de la GUI de atributos y botones (`ascendant_attributes_gui.png`, `ascendant_attribute_component.png`, `ascendant_ghost_health.png`, `ascendant_sword(_highlighted).png` — estos sí llevan nombre propio, referenciados directamente desde nuestro código), y el sonido de esquiva (`ascendant_dodge.ogg`, Vorbis válido verificado). Creados `sounds.json` y `particles/ascendant_crit.json` (la partícula de crítico usa la textura vanilla `minecraft:critical_hit`, sin arte nuevo necesario ahí). Traducido el `lang/en_us.json` completo (165 claves) del original, renombrando el namespace. Build verde.
- Fase 13 (QA) — verificación automatizada final: `clean build` y `runServer` completos sin errores propios del mod (arranque en 3.25s, todos los registros/mixins/datapack cargados correctamente). El QA jugado en partida real (comparar comportamiento contra el original) queda en manos del usuario, que ya subió el mod a CurseForge. **Con esto se completa el roadmap entero (Fases 0-13).**---
